**For the builder: what is already there** (checked on `main` at `ec2e1ca`)
- `btree_gist` is created in `0000_init.sql`, `pg_trgm` nowhere yet. `reset.ts` creates the
  database with the migration role as its owner, and both are trusted extensions in PostgreSQL 18
  (`docker-compose.yml`), so a migration may create `pg_trgm`. drizzle-kit writes neither
  `CREATE EXTENSION` nor an exclusion constraint: hand-write them after the generated SQL, as 0000
  and 0001 do; a later `db:generate` never drops what its snapshot does not hold.
- `clinics_for_user()` (`0001_auth.sql`): `LANGUAGE sql STABLE SECURITY DEFINER`,
  `SET search_path = pg_catalog, public`, then `REVOKE ALL … FROM PUBLIC` and
  `GRANT EXECUTE … TO chairside_app`. `CREATE OR REPLACE` cannot change what it returns: drop it
  and create it in the new migration, both grants again, the user filter and `m.status = 'active'`
  kept, the provider joined on `p.clinic_id = m.clinic_id AND p.id = m.provider_id`. Its reason in
  `CROSS_CLINIC_FUNCTIONS` (`tests/integration/tenant-allow-list.ts`) lists what it returns.
- `clinicsForUser()` (`src/modules/auth/memberships.ts`) maps each column through a guard
  (`toRole`, `toExtraPermissions`); `ProviderKind` and `isProviderKind()` are in `permissions.ts`,
  beside `can()`'s `linked_to_provider` and `linked_to_dentist`. `ClinicChoice` is in
  `resolve-clinic.ts`; tests build it too (typecheck finds them). `currentStaff()`
  (`src/app/_lib/auth.ts`) opens no tenant transaction: it lists the clinics through
  `clinics_for_user()` and resolves one, which is why the kind is read there (D-091).
- `memberships` is in `src/modules/auth/schema.ts`, `clinics` in `src/modules/tenancy/schema.ts`;
  a `schema.ts` may import another module's `schema.ts` for foreign keys (D-058). `memberships →
  providers` and `appointments.created_by → users` make auth's and scheduling's `schema.ts` import
  each other: that holds while every cross reference stays inside drizzle's callbacks
  (`.references(() => …)`, the table's `(t) => [...]`); no lint rule forbids the cycle.
- A composite foreign key needs `unique (clinic_id, id)` on its target

  (`MATCH SIMPLE`), which a nullable `treatment_type_id` or `provider_id` wants. Checks to copy:
  `clinics_phone_check` (E.164) and `clinics_email_check` (lower case).
