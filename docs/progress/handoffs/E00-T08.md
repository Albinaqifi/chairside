  `tests/integration/action-session-ended.test.ts`, `tests/integration/auth-login-audit.test.ts`,
  and the `d:`, `e:` and `f:` cases in `eslint-rules/architecture.test.ts`.
- **Where the risk is:**
  - The proxy no longer stops a signed-out POST that looks like a server action. That is safe
    while every action is a wrapper's (lint) and every page checks the session itself
    (suggestion 2). A route handler added later is reached the same way and must check its caller;
    the `ROUTE_HANDLERS` comment says so.
  - A sign-in now writes to the audit log and fails when it cannot: if the audit log cannot take
    rows, nobody can sign in (by design, D-071). It rests on Better Auth 1.7.7 running
    `create.after` before it sets the cookie. `package.json` allows `^1.7.7` (see the Discovered
    line on pinning it); the test "answers an error, sets no cookie…" fails if a later version
    changes that.
  - Lint is now a security guard. It does not see a `void` in front of a query (R-32), or a line
    that switches a rule off (suggestion 4).
