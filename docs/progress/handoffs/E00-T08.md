**For the reviewer and tester: look hard at**
- **The proxy (`src/proxy.ts`).** A POST with the `Next-Action` header or a multipart/form-data
  body now reaches Next.js without a valid session instead of being redirected. What can run there
  today: a server action, always made by a wrapper whose first step is the session check (lint now
  enforces it), or a page render, which the `(staff)` layout and the picker start with
  `currentStaff()` or `requireUser()`. A future route handler that takes such posts is reached the
  same way: it must check its caller itself (it needs a `ROUTE_HANDLERS` line with its reason).
- **The shared assertion in `architecture.test.ts`.** No case changed, but the one `it.each` body
  now (a) also counts the new rule ids, so the earlier cases also prove the new rules stay quiet on
  them, and (b) fails a snippet that cannot be parsed, which before would have passed a case that
  expects no report. Both are stricter; please confirm that is not a changed test (rule 8).
- **The snippet runner.** Only it gives missing paths the default project; the project's config
  keeps `projectService: true`, so a real file outside tsconfig.json fails lint. A snippet at an
  existing path replaces that file in the TypeScript project until the runner puts the real text
  back, so a later snippet that imports it sees the real file.
- **The failed login row's error.** `recordLogin` logs the cleaned error once, with the ids, and
  throws an `APIError` that carries none of it. An error of another kind would be printed again by
  the library (its logger and `console.error`), and an `APIError`'s body goes to the browser as it
  is. CLAUDE.md says to keep a caught error as `cause`; here it is logged instead. Please judge.
- **Login rows land before the cookie** because Better Auth 1.7.7 runs `create.after` at once when
  no transaction is open (`queueAfterTransactionHook`), and sign-in opens none. D-071's "Revisit
  if" covers a later version.
