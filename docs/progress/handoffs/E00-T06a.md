**For the builder: what is already there** (checked on `main` at `2d6256a`, 2026-10-04)
- No `.github/` folder; GitHub reports no workflows. The repository is private, under a user
  account. Actions are enabled, every action is allowed, and the repository does not require SHA
  pinning (the owner may tighten both, D-075).
- `pnpm check` is `format:check && lint && typecheck && test && test:integration`
  (`package.json`). Lint runs with `--max-warnings=0`; `typecheck` runs `next typegen` first. A
  fresh checkout has no `.next/`, so the README's stale-types problem does not arise in CI.
- The integration tests build their own `<db>_test` database (`tests/integration/global-setup.ts`
  calls `resetDatabase`) from `DATABASE_ADMIN_URL`, `MIGRATION_DATABASE_URL` and `DATABASE_URL`, so
  CI needs no `pnpm db:reset`. `vitest.config.ts` loads `.env`; variables already set win. The
  reset guard (`src/db/reset.ts`) needs all three URLs on the same local host and port (do not mix
  `localhost` and `127.0.0.1`), `NODE_ENV` other than `production`, and the app role
  `chairside_app`.
- `.env.example`'s values work as they are with `docker-compose.yml` (PostgreSQL 18 on
  `127.0.0.1:5433`, a healthcheck, `POSTGRES_PASSWORD` read from `.env`). No GitHub secret is
  needed.
- `pnpm audit` (pnpm 12.8.1) needs no `node_modules`. On 2026-10-04 the full audit exits 1: one
  high advisory (`braces`, GHSA-vfj7-8cjw-p6xm, no fixed version, through `eslint-config-next`) and
  one moderate (`esbuild`, GHSA-67mh-4wv8-2f99, through `drizzle-kit`), both in development tools.
  `pnpm audit --prod` exits 0. A probe showed that `--ignore` and `--ignore-unfixable` write
  `auditConfig` into `pnpm-workspace.yaml`.
- Next.js does not switch its telemetry off in CI: `next/dist/telemetry/storage.js` only keeps its
  settings elsewhere when it detects CI or Docker. It reads `NEXT_TELEMETRY_DISABLED` when the
  telemetry starts, after `.env` is loaded.
- Prettier also checks `.github/**/*.yml` (it walks dot-folders, and `.prettierignore` does not
  list `.github`): run `pnpm format` on the workflow file.
- Actions seen on 2026-10-04 (check them again before pinning): `actions/checkout` v7.0.1
  `3d3c42e5aac5ba805825da76410c181273ba90b1`; `actions/setup-node` v7.0.0
  `820762786026740c76f36085b0efc47a31fe5020` (with `node-version-file: package.json` it reads
  `engines.node`; `cache: pnpm` caches the store); `pnpm/action-setup` v6.1.0
  `ea17c68df8912ef543352723c149a84f56e3d413` (it reads `packageManager` when no version is given).
  `pnpm/action-setup`'s tag is annotated: the ref API returns the tag object, and dereferencing it
  gives the commit. `actions/checkout` keeps the token in the git config unless
  `persist-credentials: false`.
- Concurrency: GitHub cancels a waiting run in a concurrency group when a newer one joins, even with
  `cancel-in-progress: false`, and pushes to `main` and the weekly run share `refs/heads/main`. Key
  the group by the pull request's number, and give runs on `main` no shared group (for example the
  run's own id).
