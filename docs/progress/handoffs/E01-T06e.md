**Choices to look at**
- **`onSendingChange` is told from the submit, not from `pending`.** The architect named `pending` as the source. A first version did that, and the e2e showed a window: the request leaves before the transition's render and its effect run, so an Escape right after the request was sent closed the drawer. `StaffForm` now tells "sending" in `submit()` (where the `sending` ref is set), "answered" once the answer is rendered (`pending` false or a new `state`), and "answered" as it unmounts; once for each change (`told`).
- **Cancel's focus.** The cancel dialog is controlled from the drawer (`Dialog open`), outside the conditional that draws the grid, so it survives the Cancel button leaving. `onCloseAutoFocus` gives the focus to Cancel when it is still there and the cancel was not done, else to the drawer's content (`tabIndex -1`).
- **`CANCEL_REASON_LIMIT`** (`cancel-reason.ts`) repeats 200: a client component cannot import the scheduling index; a unit test holds it equal to `CANCEL_REASON_MAX`.
- After a change the toast takes the first Escape (a layer above the drawer), so the specs press Escape once for it (`closeToast`). That is how it already was.
- After an answer the layer hears "not busy" an effect and Radix's own callback later; the held-answer specs press Escape until the layer is gone (`escapeUntilHidden`), because WebKit pressed first once.
