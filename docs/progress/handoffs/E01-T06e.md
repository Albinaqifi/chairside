- Traps: (1) **a form unmounted while it sends.** After a status change the day is read again and a button's form can leave the page while its `useActionState` is still pending, as `key={block.id-action}` changes; if `busy` is a flag only set to `true` by `onSendingChange(true)`, the drawer then stays unclosable. Release it in an effect cleanup (unmount reports `false`), and prefer a count or a set of the forms sending over one boolean for the drawer, which has several forms. (2) **The Cancel button disappears when the cancel is done** (`actions` no longer has `cancel`), taking an uncontrolled `Dialog` with it and Radix's return target: control the dialog's open state or accept the unmount, but the focus must end inside the drawer. (3) **A native select under the guard:** Firefox and WebKit open it on `mousedown`; the guard's `onMouseDownCapture` must stop that within the half second. (4) **A request that never answers** keeps the drawer from closing by Escape, Close or the overlay (a reload does close it); the browser ends such a request, and `sendForm` turns a rejection into the general failure. Not built around.
