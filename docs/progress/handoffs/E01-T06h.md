**Blocked on** (one decision, `message` weight none, a test only)
`tests/e2e/booking.spec.ts:377`, "Tab reaches every field and Book", expects the Tab order from the patient box to be exactly the ten treatment chips, `select start`, `select length`, `select providerId`, Book. The Day field is a new stop in that order wherever it sits (the task puts it above the three selects, so between the chips and Start), and a date input is several stops: Chromium gives four (month, day, year, the picker button), the other two browsers other counts. So the case fails in every browser (Chromium seen: four extra `''` entries) and cannot pass unchanged: a field that Tab skipped (`tabindex="-1"`) would be an accessibility fault, and the field above the patient box would break "the patient field has the focus first". The task text says no booking spec moves; this one has to (agent rules 4 and 8: I did not touch it).
- **Option A (recommended):** change only that case's expected list: the date input is read as one stop, `input day`, whatever its number of internal stops (a run of the same entry counts once), and the list reads `[...chips, 'input day', 'select start', 'select length', 'select providerId', 'Book 08:00 with Dr. Planinska']`. About 8 lines in `booking.spec.ts` (in the loop: `element.tagName === 'INPUT' && element.type === 'date' ? 'input day' : …`, and push only when the entry differs from the last one). The loop's 20 presses are enough (10 chips, 4 stops, 3 selects, Book).
- **Option B:** move the Day field after Start, Length and Provider (below the grid, above the box): the same case still breaks (a stop before Book), and the task's "above the three selects" is not met. Not recommended.
Once you answer A, a builder applies it, runs the three browsers and sets Built.
