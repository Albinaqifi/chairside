**For the builder: what is already there** (checked on `main` at `24e220a`)
- The tables (migration 0002): `src/modules/scheduling/schema.ts` (providers, breaks with ISO
  weekdays 1–7, treatment types, appointments with `created_by` → `users.id`),
  `src/modules/patients/schema.ts` (`language` two letters, phone E.164, email lower-case) and
  `src/modules/tenancy/schema.ts` (`clinic_hours`: one row per weekday it opens; `closed_days`: one
  per date). Every key between them holds `clinic_id`. The exclusion constraint leaves out only
  cancelled, no-show and `overlap_ok` rows: a visit that is a no-show for one seed day is booked for
  another, so the plan must not overlap whatever the statuses.
- `memberships.provider_id` (nullable); `clinics_for_user()` returns the linked provider's kind.
- `seedDatabase(urls)` writes `SEED_FILES` in order; `insertRow()` only inserts (`on conflict (id)
  do nothing`, as the migration role); nothing updates a row yet. A timestamptz column takes a
  string: PostgreSQL reads `2026-10-26 09:00 Europe/Skopje` as 08:00 UTC and `2026-03-30 09:00
  Europe/Skopje` as 07:00 UTC, through an untyped parameter (probe).
- `src/db/seed/` is outside `src/modules`: the clock lint rule does not reach it. Luxon is the
  stack's library (`overview.md`) but is not installed: adding it is the owner's (agent rule 4), and
  this task needs none.
- `fake-data.ts`: eight first and eight last names in each script, `fakePhone(0…9999)`.
  `isFakeName()` takes a listed name, or a first and a last name in one script: "Dr." before a name
  is neither, so a provider's `name` is a pair and its `short_name` joins a new list. Keys holding
  "name" are checked (`short_name`, `guardian_name`, a treatment's `name`); `title`, `label`,
  `chair_label` and `note` are not.
- `seed.test.ts`: its `beforeAll` first checks that no seeded clinic exists, then seeds with the
  real day. Its login cases pin each sidebar: a provider kind widens only the owner role
  (`permissions.ts`), so linking the dentist and hygienist changes none of them.
- `index.test.ts` mocks every connection and calls `seedDatabase(urls)`: an optional day keeps it.
- The demo: providers 1369–1373 (Chair 1 to 3, hues 195, 290, 55), patients 1386–1404 (their shape
  only), treatments 1518 (Checkup 30, Cleaning 45, Filling 45, Crown prep 90, Crown fit 60, Root
  canal 90, Extraction 45, Consultation 30, Emergency 30, Whitening 60), the day 08:00–18:00.
- Traps: a seed run on a weekend has only later days, so the integration run checks counts and
  links, never statuses. The link step runs after file 01's memberships and sets a link only where
  none is set: a second run changes nothing, which `seed.test.ts` compares. A moment such as
  `completed_at` from the clock instead of the day makes two resets on one day differ.
