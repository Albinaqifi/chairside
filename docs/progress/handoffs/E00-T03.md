**What I built**
The three action wrappers in `src/app/_lib/actions.ts`: `staffAction` (who → which clinic →
allowed → valid → the handler and exactly one audit row in one `withTenant` → typed answer),
`staffRead` (the same as an action, or `.forPage(input)` in a page without the clinic check; an
audit row only when a read declares a record view) and `userAction` (who → valid → handler). A
handler says no with `return refuse('code')`. `audit.record(tx, entry)` writes one row in the
transaction's own clinic and refuses personal field names in the metadata at any depth. Errors
leave `withTenant()` and `clinicsForUser()` without query values (D-070), also when the query error
sits deeper inside another error. `chooseClinic` runs on `userAction`. `zod` 4.6.5 is a direct
dependency. How the wrappers are called and answer is recorded in D-072.

**Not done / known gaps**
- No form carries a clinic id yet, and `useActionState` (which calls an action with
  `(previousState, formData)`) is not supported directly: E00-T04 decides how forms call the
  wrappers (D-072, "Revisit if"). `asFormAction` only fits a plain form that ignores the answer.
- Nothing makes the wrappers the only way in yet: a bare server action still compiles (E00-T08).
- Commit and rollback failures: the cleaning sits in `withTenant`'s outermost `catch`, so it covers
  them by construction, but no test produces one that carries values (that needs a deferred
  constraint, which no table has, or a connection dropped between statements; a failed rollback's
  own query carries no values).
- `clinicsForUser()` is tested with a permission failure only: a constraint violation or a value of
  the wrong type cannot reach it (it is a select, and the id is checked as a UUID first).
- Issue paths: a key of a `z.map` that is a number would still show in a path. No schema uses a
  map, and a form cannot send one.
- `providerKind` is null in the permission check until E01-T01, so an owner cannot record visits
  or approve aftercare yet (as in E00-T02).
- Not clicked through in a real browser: only the no-JavaScript form posts above, not the
  JavaScript path (standard Next.js; Playwright comes with E00-T06).
- A `next dev` server started before this session (2026-10-03, 19:21) was listening on port 3000
  on every interface. My first manual run reached it through `localhost`; I repeated the run
  pinned to my own production server (`curl --resolve`), stopped only my server, and left that one
  running. I removed the synthetic rows I had added to the local development database.

**For the reviewer and tester: look hard at**
- **Three existing tests changed their setup** (`log-redaction.test.ts`,
  `log-redaction-data-errors.test.ts`, `log-redaction-search-errors.test.ts`). They test the logger
  and took their raw query error from `withTenant`, with a guard that the error still carries the
  marker. D-070 removes exactly that, so the guards failed (8 assertions, nothing else). They now
  run the same failing queries outside `withTenant` (`rawQueryError()`, as the migration role);
  every assertion and test name is unchanged. Please confirm this is not a weakened test (agent
  rule 8).
- `withoutQueryValues()` now copies a non-query error that holds one: a real error object with the
  original's prototype and fields, inner errors cleaned, loops handled. `HandlerRefused`, and any
  error without a query error inside, comes back as the same object.
- Redirects: in `staffAction` and `staffRead` only step 1 (`currentStaff()`) lets Next.js's
  redirects and prerender signals through (`unstable_rethrow`). A staff handler that calls
  `redirect()` is rolled back and answered `internal`, on purpose: its change would otherwise be
  lost silently. A `userAction` handler may redirect (no transaction).
- Step 2 compares the ids as exact strings: the right id in capitals is refused.
- `.forPage` skips the clinic check and must never be exported from a `'use server'` file;
  E00-T08's rule should report an export such as `export const x = read.forPage`.
- `audit.record()` also refuses an action or entity type that is not a code, ids that are not
  UUIDs, and a user or patient-link actor without an id (D-072). E00-T08's login row fits these.
- Try: a double submit, another role, another clinic in a second tab, a refinement or transform
  that throws (→ `internal`), a form with repeated field names or a `__proto__` field, a handler
  that throws `notFound()`.
