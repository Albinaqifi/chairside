**For the builder: what is already there** (checked in the code on `main` at `22d7723`)
- `zod` 4.6.5 is already installed as a dependency of `better-auth` (which asks for `^4.5.4`).
  Adding it directly at that version changes no code in the tree.
- `withoutQueryValues()` in `src/lib/query-errors.ts` cleans an error that is itself a query error,
  and that error's cause. An error that is not a query error is returned unchanged, even when a
  query error sits in its `cause`: D-070 needs that case too.
- Drizzle wraps the PostgreSQL error, so the code sits on `error.cause` (`pgErrorCode` in
  `tests/integration/fixtures.ts`). `withoutQueryValues()` keeps it there.
- `withTenant` (`src/db/tenant.ts`) rethrows the error from `fn` unchanged today, and a failed
  reset never replaces it (D-061). It refuses a nested call (D-060).
- `currentStaff()` (`src/app/_lib/auth.ts`) is memoised per request and redirects to `/login` or
  `/choose-clinic`. A redirect thrown inside a server action is how Next.js sends the browser
  elsewhere, so step 1 can reuse it. The E00-T02 tests call it with `next/headers` mocked
  (`tests/integration/auth-session-cookie.test.ts`).
- `audit_log` exists since migration 0000: the app role may insert and select, never update or
  delete. `actor_id` and `entity_id` are text; the check constraint allows actor types `user`,
  `patient_link` and `system`. No migration is needed.
- `isPersonalField()` is exported from `src/lib/personal-fields.ts`; the clock is in
  `src/lib/clock.ts` (`fakeClock` for tests).
- The only server action today is `chooseClinic`. Its form also works without JavaScript (a plain
  multipart POST, checked by the E00-T02 tester); keep that working.
- How a form gets the clinic id is E00-T04's job. E00-T03 needs no form: the tests call the actions
  directly.
