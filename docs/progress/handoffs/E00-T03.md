**Suggestions** (not blocking; each is also a line on the board's Discovered list)
1. **A failed query kept somewhere other than an error's own properties still prints its values.**
   `withoutQueryValues()` (`src/lib/query-errors.ts`) walks `cause`, an AggregateError's `errors`
   and own properties whose value is an error or a list of errors. A query error inside a plain
   object (`Object.assign(err, { details: { db: e } })`), inside a Map, or in a thrown value that
   is not an Error (`throw { cause: e }`) is returned as it is, and `util.inspect` prints its
   `params` (scratch script on `308457d`). Every case D-070 names is covered; these are not.
   Cheapest guard: E00-T08 turns on type-aware linting anyway, so add
   `@typescript-eslint/only-throw-error` there (it also catches suggestion 2's `throw refuse(…)`),
   and say in `query-errors.ts` which shapes are walked.
2. **A thrown refusal is answered `internal`, and `refuse()`'s comment over-promises for
   `userAction`.** `throw refuse('not_found')` is treated as unexpected: logged (as `err: {}`)
   and answered `internal`. That fails safe, but a builder will try it. And `refuse()`'s comment
   says "Nothing the handler did is kept", which holds for `staffAction` and `staffRead` only: a
   `userAction` has no transaction, so a cookie set before `return refuse(…)` stays set. Say so in
   the comment, or have the wrappers treat a thrown refusal like a returned one.
3. **Two stated behaviours have no test.** (a) D-072: a staff handler that calls `redirect()` or
   `notFound()` is rolled back and answered `internal`. Nothing stops a later edit from adding
   `unstable_rethrow` to step 5's `catch`, which would send the browser on with the change
   silently lost. (b) D-069: the clinic check comes before the permission check. An action the
   person may not do, sent with another clinic's id, should answer `clinic_changed`, not
   `forbidden`. One short test each in `action-wrappers.test.ts`.
4. **`src/modules/audit/record.ts` (line 102) says the JSON error "names neither a key nor a
   value".** For a loop, V8's message names every key on the path ("property 'x' closes the
   circle"), and that error is kept as `cause`, so `internal()` logs it. Only key names, so it is
   small. Fix the comment, or leave the `cause` out.
5. **An audited read writes its "viewed" row on every render of its page.** Next.js 16 does not
   fully prefetch dynamic routes by default, but `<Link prefetch={true}>` renders the full page
   before any click (`node_modules/next/dist/docs/01-app/03-api-reference/02-components/link.md`).
   A patient profile that declares its view would then log views nobody saw. E01-T03: no full
   prefetch on links to a patient record, and a comment where the audited read is declared.

   put the input there.** The wrapper answers `internal` and logs the error, as the task says. A
   probe with `z.string().transform((s) => JSON.parse(s))` sent a marker: the log line held it

   them has the same trap. Zod's rule is that transforms report problems with `ctx.addIssue` and
   never throw. Suggest: say so next to the wrapper example in `CLAUDE.md`; let E07-T07's log
   canary include a throwing transform; consider `input` for the personal fields.
