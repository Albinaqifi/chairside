**Findings**
1. `data` · The profile's address in capital letters (`/patients/019A0000-5EED-7000-8000-000000001022`) opens the
   patient, and the `patient.viewed` row names them as typed: `entity_id` is `019A…`, not the patient's own
   `019a…`. `z.uuid()` accepts upper case and Postgres compares a uuid without case, so the read finds the patient, but
   the audit entity is text taken from the input. Every later query for "who viewed this patient" (`entity_id = <id>`:
   E07-T01's viewer, the access report) misses that view, and the record view is the one trace of who read a patient.
   Seen on the seeded dev database and with the test below. Should: one row naming the patient by the id the record
   holds, however the address was written. A fix at the schema, since `readPatient` can be called without the page:
   `z.uuid().transform(...)` to lower case (with `ctx.addIssue` rules of the conventions), or the audit's `entityId`
   from the profile read, as the builder chooses. The same shape is likely in other audited reads and actions that take
   a `z.uuid()`; not checked, outside this task.
