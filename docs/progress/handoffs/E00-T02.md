**What I built**
Login with email and password through Better Auth (D-006): sessions in our database that end
30 minutes after the last request, httpOnly cookies (Secure as soon as the app is on https),
sign-in attempts limited to 5 per minute per client address with the counters in the database,
and no self sign-up. The auth tables are global (on the meta-test allow-list); `memberships` is
a tenant table with Row-Level Security. The clinic a user acts for is resolved on every request
from their active memberships, with a clinic picker for people who belong to several (D-062).
Roles and permissions are one typed table that mirrors scope-v1.md, with a pure `can()`. A
protected `(staff)` layout with a placeholder page, a plain login page, logout, and `src/proxy.ts`
for the quick redirect of requests without a session cookie.

**Not done / known gaps**
- There is no seed yet (E00-T05). To log in by hand, make an account as described under "For
  the tester". `createStaffUser()` in `@/modules/auth` is what the seed and `clinic:create` call.
- `memberships.provider_id` is not there yet: providers come with E01-T01, which adds the column
  and its foreign key. `can()` already takes `providerKind` in its extras; until then callers pass
  `null` (an owner cannot record visits or approve aftercare before that).
- Login and logout are the library's routes, called from the browser; they do not go through the
  action wrapper (E00-T03 builds it). The clinic picker's `chooseClinic` is a plain server action
  and writes no audit row (board, Discovered: which login event is audited, and with which clinic).
- The rate limit is per client address only. A clinic's shared address can be locked for a minute
  by five failed attempts of anyone there (R-33). Which proxy header to trust is for E00-T07.
- The pure rule tests inside `tenant-tables.test.ts` ("meta-test rules") used a fixed list of two
  tables, so adding allow-list entries made them report those entries as missing. I made that
  list follow the allow-lists and passed an empty allow-list to the two view and function rule
  tests. Every assertion is still there; the checks against the real database are unchanged.
- A layout cannot protect routes on its own during client-side navigation (Next.js guide,
  "Layouts and auth checks"), so every page under `(staff)` calls `currentStaff()`; E00-T03's
  wrapper must as well.
- Not clicked through in a real browser (no Playwright before E00-T06). The login form's
  JavaScript path uses the library's standard client (`authClient.signIn.email`); I verified the
  same HTTP calls with curl, and the picker's no-JavaScript form path.
- Better Auth logs "User not found" and "Invalid password" (no identifiers) at warn level, through
  our logger. The server log can tell the two apart; the response cannot.
- `BETTER_AUTH_SECRET` is a new environment variable holding a secret (agent rule 4). It is
  inherent to the library the task names, so I did not stop: `.env.example` has a local-only value
  and `.env` files made before this task lack both new lines (README, "If something goes wrong").
