**For the builder: what is already there** (checked on `main` at `c1c7032`)
- **The probe:** pg-boss 12.37.1 on PostgreSQL 18, in a scratch database since dropped, run as
  `chairside_app` with every interval at its minimum: 5,006 statements in 165 s, no DDL, no error.
  - `import { PgBoss, getConstructionPlans } from 'pg-boss'`: named exports, no default; ESM; Node
    ≥ 22.12; it type-checks with our `skipLibCheck: true`. `@opentelemetry/api` (^1.9.0) is a peer
    it imports at load: pnpm installs peers by default; check the lockfile and the image hold it.
  - `getConstructionPlans('pgboss')` gives one string, 481 lines: `BEGIN;`, `SET LOCAL` timeouts,
    an advisory lock, the schema, the `job_state` type, six functions (none SECURITY DEFINER; no
    view, extension or sequence), eleven tables (`job` partitioned by queue name, its default
    partition `job_common`; `queue_stats` by day), a `DO` block that makes `queue_stats_<today>`
    and `<tomorrow>` (UTC), the version row (45), `COMMIT;`. Left in, that `COMMIT;` commits the
    migrator's own transaction: the schema survived the outer ROLLBACK.
  - Its defaults do not fail safe: with the schema in place, `start()` and `createQueue()` succeed
    as the app role with every default. With `migrate: false`, `start()` reads the version row and
    throws "pg-boss is not installed" or "pg-boss database requires migrations".
  - What changes the schema while it runs, each off (D-104): `persistQueueStats` (a partition a
    day: the app role's errors start two days after the migration), `createQueue(…, { partition:
    true })`, `reindex` (only on indexes the role owns: none, but set it off), `TestClock.attach()`,
    `deleteAllJobs()` without a name (TRUNCATE).
  - Grants that worked: `USAGE` on the schema; DML on `version`, `queue`, `schedule`, `job`,
    `job_common`, `job_dependency` and `instance` (maintenance prunes `instance` even with
    `registerInstance: false`). The two functions it calls, `job_now()` and
    `create_queue(text, jsonb)`, keep PostgreSQL's default EXECUTE; not needed: `bam`, `warning`,
    `queue_stats`, `subscription`.
  - No `'error'` listener: an error in a background pass is an unhandled rejection, and the process
    exits with code 1. pg-boss writes nothing to the console.
  - A handler's throw is kept in `output` as `serializeError(err)`: name, message, stack; for a
    database error also `code`, `constraint`, `table` and `detail` (a row's values); a `cause` too.
    Kept 7 days by default (`deleteAfterSeconds`).
  - `stop({ graceful: true, timeout, close: true })` waits up to `timeout` (default 30 s) for
    running handlers, then marks those still running "pg-boss shut down while active" (retried
    later), aborts `job.signal` and ends its pool; the handler itself runs on. No signal handler of
    its own. Render waits 30 s by default before it kills a process (E00-T07c checks it).
  - `schedule(name, '* * * * *')`: about 1 s after each minute; the first run about 2 s after
    `schedule()`. A six-field cron still runs once a minute. In a test: `cronMonitorIntervalSeconds:
    1`, `cronWorkerIntervalSeconds: 1`, `pollingIntervalSeconds: 0.5`, and a `clock` whose `now()`
    runs 60,000 ms further ahead each step gave three runs in 6 s. A fresh queue name per test: a
    second run under the same name found its minutes already used.
  - `instance` rows hold the host, the pid, an allow-list of options (no connection string) and
    pool counts, never an error's text.
- `src/db/migrate.ts` runs every pending migration in one transaction (drizzle's migrator).
  `pnpm db:generate --custom --name pgboss` makes an empty one, as 0004 was made.
- The meta-test (`tests/integration/tenant-tables.test.ts`) lists every table in every non-system
  schema, partitions included, and fails for a listed name that does not exist: a dated partition
  fits no list. It checks views and SECURITY DEFINER functions in every schema too.
  `tenant-allow-list.ts`'s comment "The app role reaches only the auth library's tables among them"
  changes with the grants.
- `chairside/database-access`: `isDriver()` counts every `pg-…` package (`architecture.test.ts`
  reports `import PgBoss from 'pg-boss'` in a module). `src/db/` passes no driver on (D-084): export
  functions; one that returns the PgBoss object is a review check.
- `src/db/client.ts`: our pool, `closeDb()`; `connect()`'s comment "Only withTenant uses it" is no
  longer true (E00-T07a review, `none`). `databaseProblem()` (`src/db/health.ts`) never throws, but
  holds its client without an `'error'` listener: in the worker, which has no Next.js handler, a
  connection that ends during its one query would end the process (the host restarts it).
  Acceptable at start; or listen as `tenant.ts` does.
- `src/db/clinic-create.ts` is the model of a tsx script: `import.meta.main`, `process.exitCode`,
  `closeDb()` in `finally`. The image runs a script as `node --import tsx <file>` (D-103), and
  `docker stop` sends SIGTERM to that Node.js.
- Windows: `child.kill('SIGTERM')` ends a child process at once, without its handler;
  `process.emit('SIGTERM')` runs the handler in the test's own process. CI runs Linux.
- `docs/runbook.md`: a test reads every `BETTER_AUTH_SECRET=` in it and expects `.env.example`'s
  value; the worker needs no auth setting, so its command sets none.
- Integration tests share one database, one file at a time; their `DATABASE_URL` is the test
  database's app role; `fixtures.ts` has `migratorPool()`, `appPool()`, `expectPgError`, `PG`.
- Must not change: the web and its health check, the meta-test's logic, the lint rules.
