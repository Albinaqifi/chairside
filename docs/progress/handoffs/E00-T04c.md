**For the reviewer and tester: look hard at**
- `data` The clinic id: `StaffForm` reads it only from `useFrameClinic()` and has no clinic prop
  (a type test); the layout fills `FrameClinic` from its own `currentStaff()`. The demo's
  `askedAction` passes the id it is given to a wrapper-made action, unchanged.
- `data` `onSubmit` dispatches instead of React's form action (D-092). Without its script the
  form's HTML action is React's `javascript:` URL; nothing can reach a URL. Lint passes the form.
- `sendForm` catches everything but Next.js's router errors (`unstable_rethrow`): an ended
  session's redirect to `/login` still goes through.
- `clinic_changed`: the reload button empties the form, then reloads; what was typed is dropped.
- `noValidate` on every staff form; after an answer the focus goes to the first invalid field,
  or back to the button when it was lost.
- `useToast()` without a Toaster renders and throws only when called, so the sidebar test renders.
- Logout: an `{ error }` answer from the auth library now fails too (before, it went to `/login`).
- Tests replace React's `useActionState` (`staff-form.test.ts`) to choose the state and catch the
  bridge. Props whose `children` TypeScript requires are built as typed objects before
  `createElement`: `react/no-children-prop` reads literals only.
- D-086's review checks: no spread of a type parameter's props; `FieldControlProps` spread onto
  `Input` holds no `formAction` or `formMethod`.
