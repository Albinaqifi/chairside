**For the builder: what is already there** (checked on `main` at `220d9d2`)
- The frame: `(staff)/layout.tsx` renders the sidebar from `currentStaff()`; its clinic id is
  `staff.clinic.clinicId`. It does not render again on navigation (its comment says why). Every page
  under `(staff)` calls `currentStaff()`: Today (`page.tsx`), six through `placeholder-page.tsx`.
- The wrappers (`src/app/_lib/actions.ts`): `action(clinicId, input)` answers `{ ok: true, value }`

  answer (the clinic picker).

  the nearest error boundary (Next.js, `10-error-handling.md`: "unhandled errors inside
  `startTransition` … bubble up"). The app has no `error.tsx`, so the person would get Next.js's
  error screen: the pattern catches the rejection and shows the general failure.
- The login form calls `void submit(event)`: when `authClient.signIn.email` rejects, `pending`
  stays true and the button stays disabled. `login-form.test.ts` pins the server's HTML (D-076):
  add cases, change none (agent rule 8).
- `LogoutButton` (`src/app/_lib/logout-button.tsx`) stands in two layouts, the sidebar (staff) and
  the clinic picker (auth): its failure message must show in both.
- `src/ui/`: Button (`primary`, `secondary`, `quiet`), Input, Label, Card, Badge, Empty, Logo. No
  toast, no field.
- Tokens: the demo toast's colours (`oklch(0.26 0.03 200)` on `oklch(0.97 0.01 195)`), 12 px radius
