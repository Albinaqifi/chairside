**For the builder: what is already there** (read on `main` at `098da9c`; no probe was run)
- `src/modules/scheduling/booking.ts`: `createAppointment` makes `localStart`, `startsAt` and `endsAt` in SQL and checks the skipped local time with `at time zone` twice; the move needs the same lines, so they go into one function that both call (the booking's tests stay as they are). It locks the provider's row `for update` first and never an appointment.
- `chair.ts`: `sameVisitHoldsChair` and `chairClashes` take `Moment` (a SQL or a Date) and **find the visit being moved**, as it holds the chair. That is the trap: a move to an overlapping time with the same provider, or to the same start with another provider and the same patient, would be refused by its own old place. Add the optional `exceptId`.
- `status-change.ts`: `changeAppointmentStatus` is the pattern to copy: the patient's row first (the caller's `patientIsActive`, `patients.patientStatus`), then the appointment `for update` read again under the lock, then the provider; `emit` once after the write; refusal codes returned, never thrown; `updatedAt` from `now`.
- `events.ts`: `AppointmentChanged` has `appointmentId`, `from`, `to`, `at`. Add `moved?: boolean`, optional, so T06a's tests that compare an event are untouched; say so if one has to change.
- `appointments.ts` (`appointmentsOnDay`): each visit has `actions`, computed from the state machine; add `movable` from one exported function that the move also uses. `day.ts` (the mapping at about line 239) passes `actions` on: pass `movable` the same way.
- `appointment-actions.ts`: the file already holds `changeAppointmentStatus` with the lower-casing transform for the id, and `refresh()` and `revalidatePath('/patients')` after a change; the booking's action in `actions.ts` is the model for `day` (`isShownDay`), `start` (`minutesOfStart` in a transform with `ctx.addIssue`, never a throw) and `anyway` (a hidden `'true'`). The `'use server'` file may hold several actions and exports nothing else but types.
- `src/app/action-permissions.test.ts` lists every action × every role: add the new one.
- Traps: (1) the exclusion constraint `appointments_no_double_booking` ignores a row with `overlap_ok`, and the update of a row is judged against the other rows, never its own old version; (2) a move across a day of 23 or 25 hours: the start is a local time, the length is real time, the new end is the new start plus the old end minus the old start; (3) lock order: patient, appointment, then the providers by id; a booking takes the provider only, so there is no cycle; (4) `nothing_changed` is judged on the moments (the same provider and the same `starts_at`), not on the typed day and start; (5) the logger and the audit: no value, no id other than the appointment's, in the metadata.
- Do not change: the booking's behaviour, the restore, the state machine, `StaffForm`.
