**For the reviewer and tester: look hard at**
- The lock (`lockCatalogue`): `pg_advisory_xact_lock(hashtextextended('treatment_types:' ||
  current_clinic_id()::text, 0))`, chosen over row locks because a clinic with no type has no row to
  lock (the `clinic:create` case). Released at commit or rollback; two clinics on one hash only wait.
- The name comparison is in JavaScript (`trim().toLowerCase()`), not SQL `lower()`, so a database
  whose collation does not lower Cyrillic still sees "Пломба" and "ПЛОМБА" as one name.
- My choices inside the task's words: an inactive type may be renamed to an active one's name (it is
  offered nowhere; making it active again is then `name_taken`); a second press on a type's state is
  refused (`already_inactive` / `already_active`), so no audit row says a change that did not happen;
  the length schema takes any whole 1–1440 minutes (the drawer's `LENGTH_MAX`), as the select keeps a
  type's own length outside the steps; a price above the column's integer is `price_too_high` (a
  refusal the task did not name: nine digits in a two-digit currency overflow it); in a currency with
  no decimals "12.00" is `price_decimals` too.
- `treatment-type-fields.ts` imports no value of `@/modules/scheduling` (the tab runs in the browser):
  `PRICE_MINOR_MAX` copies `TREATMENT_PRICE_MAX`, held equal by its unit test.
- The e2e runs in the second seeded clinic, which has no types: `booking.spec.ts` counts the first
  clinic's ten chips, so nothing here may add to or deactivate them, even for a moment.
- Layout (the demo has no such screen, design-reference.md): each row the name (with an "Inactive"
  pill, the archived patient's grey), a muted line "45 min · MKD 1,500.00 · Needs aftercare", then Edit
  (secondary) and Make inactive (teal, as every staff form's button) at its right; the add form under
  a line, its fields in one row on a wide screen; the edit dialog's fields one under another.
